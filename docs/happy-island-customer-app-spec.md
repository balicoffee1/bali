# Happy Island — клиентское приложение: полная спецификация поведения

Документ для агента (дизайн / ревью / тесты / доработки). Описывает, **что реально делает приложение**
по исходному коду, экран за экраном, диалог за диалогом, с точными текстами.

- **Источник:** `/Users/egor/Projects/happy_island/happy_island` (Flutter, отдельный репозиторий
  `github.com/vektemok/Happy-Island`), коммит `f1621c4` + незакоммиченные правки на момент 2026-09-25.
  Бэкенд — этот репозиторий (`Island-Bali`), тоже с незакоммиченными правками.
- **Как получено:** прочитан весь код `lib/` (≈26 тыс. строк). Приложение **не запускалось** — визуальные детали
  (отступы, анимации) взяты из кода, а не со скриншотов. Всё, что я не смог подтвердить чтением кода, помечено
  **[не проверено]**.
- **Язык интерфейса:** только русский. Часть строк лежит в `packages/l10n/app_ru.arb`, но большинство
  захардкожено прямо в виджетах. Текст ниже приведён дословно, включая опечатки.
- **Платформы:** iOS (`happy.island`) и Android; есть ландшафтные размеры для главной/меню/карточек.
  Системный масштаб шрифта **игнорируется** (`TextScaler.noScaling`), тёмной темы нет, смены языка нет.

Обозначения: «→» — переход/следствие, **[БАГ?]** — расхождение или вероятная ошибка (сведены в разделе 17).

## 0. Что в приложении есть и чего нет

Есть (клиентская роль):
1. Главная: скидочная карточка, «Сделать предзаказ», погода, «Музыка дня», баннер франшизы.
2. Меню: сезонные разделы + категории → список напитков → карточка напитка.
3. Корзина → выбор времени → комментарий → отправка баристе → оплата СБП → статус заказа.
4. Диалоги жизненного цикла заказа (ожидание, смена времени, «спасибо», отмена, оценка).
5. Профиль: имя/фамилия, юридические документы (PDF), «Позвать друзей», выход, удаление аккаунта.
6. Выбор города и кофейни.
7. Вход/регистрация по SMS-коду (один и тот же поток).
8. Push-уведомления (только системные, без экрана).
9. Заявка на франшизу (диалог на главной).

Есть (роль бариста, тот же билд): отдельный режим `/staff` — раздел 14.

**Нет в приложении** (не искать и не проектировать «как будто есть»):
- **История заказов** — экрана нет вообще. Клиент видит только текущий (последний) заказ.
- **Банковские карты** — репозиторий/блок есть и профиль их подгружает, но UI нет; оплата только СБП.
- **Экран/лента уведомлений** — есть только системные push и локальные баннеры.
- **Реферальная программа с бонусами** — есть только кнопка «поделиться ссылкой на магазины».
- Бонусные баллы, промокоды, избранное, поиск по меню, фото напитков, описание/состав/КБЖУ, отзывы на товар,
  выбор способа оплаты (кроме СБП), оплата в кофейне, адрес/карта кофеен, чат с поддержкой, deep-link'и внутрь
  приложения, онбординг.

## 1. Навигация и глобальные правила

### 1.1 Маршруты (go_router)
| Путь | Экран | Заметки |
|---|---|---|
| `/home` | Главная | стартовый, без анимации перехода |
| `/menu` | Меню | вкладка |
| `/cart` | Корзина | вкладка |
| `/userProfile` | Профиль | обычный маршрут поверх оболочки (нижнего меню нет), стрелка назад |
| `/privacy_terms` | PDF политики | объявлен, из UI не используется |
| `/staff` | Режим бариста | глобальный `redirect`: если сессия `is_staff` → сюда |

Три вкладки — `StatefulShellRoute.indexedStack` (состояние вкладок сохраняется). Всё остальное — модальные
диалоги/шторки поверх корневого навигатора.

### 1.2 Два «замка» на действиях (`redirectFunction`, `core/util/redirect.dart`)
Порядок проверки при тапе на защищённое действие:
1. **Нужен вход?** Если `checkAuth` и пользователь не авторизован → шторка входа (раздел 3), действие не выполняется.
2. **Выбрана кофейня?** Если `CoffeeShopCubit.state == null` → диалог «Выберите город» (раздел 4) и после выбора
   кофейни *всегда* `go('/menu')`; исходное действие **не** повторяется.
3. Иначе: перезагрузка корзины (`LoadedCart`) и выполнение действия.

Где какие замки: вкладка «Меню» — только замок 2; вкладка «Корзина» — 1+2; аватар-профиль — 1+2; «Главная» —
без замков, но см. 2.3.

### 1.3 Глобальные поведения
- Любой тап вне поля ввода снимает фокус (клавиатура прячется).
- Выход из аккаунта (любым способом, в т.ч. когда сервер отверг refresh-токен) → оболочка переключает вкладку на
  «Главная».
- Сессия: access-токен в `Authorization: Bearer`. На 401 клиент один раз пробует `POST /api/token/refresh/`
  и повторяет запрос; если refresh мёртв (400/401) — разлогин. Разлогин также на `detail`
  «Пользователь не найден» / «Учетные данные не были предоставлены.» / «Данный токен недействителен…».
  Нет сети ≠ разлогин.
- Данные пользователя хранятся в `SharedPreferences`: `auth_session`, `selected_city_name`,
  `selected_coffee_shop` (JSON целой кофейни), `fcm_token`, очередь `order_dialog_ack.pending`.
- Базовый URL по умолчанию `http://79.174.81.151/` (`--dart-define BASEURL` переопределяет). iOS разрешает
  произвольный HTTP (`NSAllowsArbitraryLoads`). WebSocket выводится из того же URL (`ws://host:80/ws/orders/`).

### 1.4 Запуск приложения
1. Кадр откладывается, пока не инициализируется Firebase и `SharedPreferences`.
2. Сразу (без экрана-пояснения) показывается **системный запрос разрешения на уведомления** (iOS и Android 13+).
   Отказ никак не обрабатывается и не объясняется.
3. Фоном стартуют: загрузка городов/кофеен (`CityBloc`), погода, скидка (`/api/bonus_system/loyalty/`),
   корзина (`/api/cart/view_cart/` — до входа вернёт 401, сессию это не сбрасывает, т.к. нет сохранённой сессии),
   WebSocket заказов (только при наличии сессии), разбор очереди подтверждений диалогов.
4. Открывается `/home`. Splash-экрана/онбординга нет.

## 3. Вход и регистрация (`LoginSheet`)

Регистрации отдельно нет: **один поток «телефон → SMS → код»**; новый пользователь создаётся на сервере.
Клиент **всегда** зовёт `POST /api/users/get_or_create_user/` (не `/api/users/auth/`); флаг `is_registered` из
ответа на запрос кода парсится, но интерфейс от него не меняется.

**Триггеры:** тап по защищённому действию без входа (Корзина, профиль, «Получить» скидку, «Добавить» в корзину).

**Контейнер:** модальная шторка (`showModalBottomSheet`, корневой навигатор, safe-area, скругление сверху 18),
высота 55 % экрана, поднимается над клавиатурой, крестик справа сверху. Заголовок (14/600): « Чтобы сделать заказ,
войдите в приложение» (2 строки). Внутри `PageView` без свайпа из двух шагов.

### Шаг 1 — данные
| Поле | Подсказка | Правила |
|---|---|---|
| Имя | «Ваше имя *» | обязательно; первая буква автоматически заглавная; при валидности справа зелёная галочка; автофокус при открытии |
| Фамилия | «Ваша Фамилия 😉» (без звёздочки) | **фактически обязательна** — кнопка не включится без неё **[БАГ?]** |
| Телефон | «Номер телефона *» | маска `+7 (###) ###-##-##`, цифровая клавиатура; валидатор ждёт `+7`/`8` + 10 цифр |

Кнопка «Получить код» (градиент): серая и нажатие блокируется, пока все три поля не валидны. Под ней мелкий серый
текст согласия (10/500): «Я соглашаюсь на **обработку персональных данных** и ознакомлен с **Политикой
конфиденциальности**, **Пользовательским соглашением** и **Публичной офертой**.» — синие ссылки, каждая открывает PDF
на весь экран (`PDFViewSheet`, кнопка-крестик слева в шапке). Галочки согласия нет, согласие неявное.

Нажатие → `POST /api/users/registration_get_code/ {"login":"+7XXXXXXXXXX"}` → на экране кнопка серая, идёт запрос.

### Шаг 2 — код
- Текст (12/500, серый): «Код был отправлен на ваш номер телефона:» + строка с маской номера.
- 4 ячейки PIN (серые боксы 12 px, цифровая клавиатура, шрифт 32/500), автофокус. **Ввод 4-й цифры сразу
  отправляет код** (кнопки «Подтвердить» нет). Пока идёт запрос — маленький спиннер 20 px под полем и повторный
  ввод игнорируется.
- Ссылка-кнопка (12/500, синяя) «Запросить еще через N сек» (неактивна) → «Запросить еще раз» (активна).
  Таймер 60 с, либо `retry_after` из ответа 429 сервера. Повторный запрос берёт имя/фамилию/телефон из полей шага 1.
- **Назад к шагу 1 нет** (страницы не листаются, стрелки нет). Сменить номер — только закрыть шторку крестиком и
  открыть заново.

Успех: сохраняется сессия (`token.access/refresh`, `id`, `is_staff`), обновляется корзина, шторка закрывается,
пользователь остаётся на том же экране (защищённое действие **не** повторяется — надо нажать ещё раз).
Если `is_staff` — работает `redirect` на `/staff` **[не проверено: срабатывает сразу после входа или при следующей
навигации]**.

### Ошибки входа (красный плавающий снэкбар, 3 с, всегда с префиксом «Ошибка: »)
Текст берётся из `error`/`message`/`detail` ответа сервера как есть:
- запрос кода: `"login must be phone number"` (400), `429` «…» + `retry_after` (запускает таймер), `503`
  «Сервер отправки СМС …»;
- ввод кода (400): «Требуется код подтверждения из SMS.», «Неверный код.», «Код не запрашивался. Запросите новый код.»,
  «Код уже использован. Запросите новый код.», «Срок действия кода истёк. Запросите новый код.»,
  «Превышено число попыток. Запросите новый код.».
- При любой ошибке кода: поле PIN **трясётся**, очищается, фокус возвращается. Для трёх последних ошибок шаблон
  подразумевает возврат к шагу 1 — в приложении такого перехода **нет**, пользователь просто жмёт «Запросить еще раз».
- Сеть недоступна: снэкбар с `DioException.message` либо «Произошла ошибка при входе».

Тестовый вход для ревью магазинов: `+7 777 777 77 77` / код `0000` (см. `docs/sms-auth-contract.md`; включается флагом
`SMS_TEST_LOGIN_ENABLED` на сервере).

### Выход из аккаунта
Не диалог: кнопка «Выйти из аккаунта» в профиле (раздел 10) → токены удаляются, FCM-токен отвязывается
(`/api/users/fcm/unregister/`) и удаляется в Firebase, вкладка → «Главная», сокет отключается. Подтверждения нет.

## 4. Выбор города и кофейни

Два последовательных модальных диалога. Поднимаются при: тапе на кнопку города, «Сделать предзаказ», тапе на
Меню/Корзину/Профиль без выбранной кофейни, и в конце — по цепочке замков.

### 4.1 «Выберите город» (`SelectCityWidget`, `DefaultDialog`, крестик)
- Список городов (`GET /api/coffee_shop/list_city/`): серые плитки (`#F1F5F9`, радиус 12), название 12/600,
  справа круглая радио-кнопка с жёлтой точкой (`#FFB800`). Одиночный выбор. Изначально отмечен сохранённый город.
- Кнопка «Выбрать » (градиент).
- **[БАГ?]** Если нажать «Выбрать», не тапая по строке, берётся **первый город списка**, даже если радио показывает
  другой (сохранённый) — `select_city_widget.dart:129`.
- При «Выбрать»: сохраняется `selected_city_name`, **стирается выбранная кофейня**, перезапрашиваются погода и
  кофейни города, диалог закрывается и сразу открывается 4.2.
- Пустой список: сам диалог не открывается (кнопка города вместо этого повторяет загрузку); если открыт — «Выбрать»
  ничего не делает.

### 4.2 «Выберите адрес» (`SelectCoffeeShopDialog`, 85 % ширины × 60 % высоты, без крестика)
- Заголовок «Выберите адрес,» (20/700) + подзаголовок «где Вам будет удобно\nзабрать заказ » (14/600, серо-голубой).
- Список кофеен города: плитки с текстом «ул. <улица>». **Номер дома и часы работы в списке не показываются**
  (строки «Открыто до 22:00» в l10n есть, но не используются).
- Внизу подсказка (10/500, по центру): «Обратите внимание, что от выбранного адреса зависит наше Меню.»
- Кнопки: «Назад» (→ диалог города) и «Заберу отсюда» (→ подтвердить). Если ничего не тапнули — берётся ранее
  выбранная кофейня либо первая в списке.
- Состояния: загрузка → `CircularProgressIndicator` по центру (заголовок остаётся); нет кофеен → «В выбранном городе
  пока нет кофеен» + только кнопка «Назад».
- «Заберу отсюда»: кофейня сохраняется (JSON в prefs), запускается загрузка категорий и сезонного меню этой точки,
  вызывается `onClose` (если был), диалог закрывается, **всегда `go('/menu')`**.
- Данные выбранной кофейни (часы работы) автоматически освежаются при каждой перезагрузке списка кофеен.

### 4.3 Ограничение смены города
Пока в корзине есть позиции (и пользователь вошёл) — сменить город нельзя (снэкбар из 2.2).

## 7. Добавление товара (шторка `CreateOrder`, режим `create`)

Модальная шторка, 88 % высоты, скругление сверху 18, крестик справа сверху. Прокручивается.

**Сверху вниз:**
1. **Карточка товара** — серая плашка: слева иконка категории, название напитка (20/700, текст залит градиентом цвета
   плитки), под ним подпись — название категории.
2. **Цена** — «N ₽ » (20/700): цена размера + цена добавок (одна позиция).
3. Разделитель, подпись «Объем:» (12/600, серая).
4. **Размеры** — кнопки только для размеров с заполненной ценой: серый бокс 45 px с иконкой стакана (30/40/50 px для
   S/M/L) и буквой `S`/`M`/`L`. Выбран — стакан чёрный, буква тёмная; иначе стакан `#D9D9D9`, буква серая.
   Объёмы в мл и цена по размерам **не показываются**, меняется только итоговая цена. По умолчанию — первый
   заведённый размер.
5. **Температура** зависит от каталога (`temperature_type`):
   - `All` — строка «❄ Холодный напиток» и переключатель (включён — голубой градиент). По умолчанию «горячий».
   - `Hot` — статичная строка «Только горячий»; `Cold` — «❄ Только холодный». Выбора нет, на сервер уходит значение
     каталога.
6. **«Добавки:»** (только если у товара они есть) — переносимый ряд чипов «<название> [N ₽]». Выбранная —
   оранжево-красный градиент, белый текст. У выбранной добавки, имеющей **вкусы**, сразу рядом появляются
   контурные чипы вкусов (одиночный выбор внутри добавки, повторный тап снимает; выбранный — красная рамка).
   Цена вкуса отдельно не берётся: деньги только за добавку и только когда вкус выбран.
7. Оранжевое предупреждение «Выберите вкус: <добавка>, <добавка>» пока у какой-либо выбранной добавки нет вкуса
   — кнопка при этом серая и не нажимается.
8. Красное «У товара не заполнена ни одна цена — заказать его нельзя» — если нет ни одного размера с ценой; кнопка
   серая.
9. **Кнопка «🛒 Добавить»** (градиент). Во время запроса серая (спиннера нет).

**Количество в этой шторке выбрать нельзя** — всегда `1`. Повторное добавление такого же (размер + температура +
набор добавок + набор вкусов) увеличит `amount` существующей строки на сервере; иная комбинация — новая строка.

**Отправка:** гость → шторка входа (замок 1); нет выбранной кофейни → красный снэкбар «Ошибка: Сначала выберите
кофейню»; иначе `POST /api/cart/add_to_cart/<город>/<улица>/` `{product_name, quantity, temperature_type, addons,
flavors, size}`.
- Успех: шторка закрывается, белый снэкбар «Товар добавлен в корзину», корзина перезагружается.
- Ошибка: шторка закрывается, красный снэкбар «Ошибка: Error: <технический текст Dio> <Город> <Улица>»
  **[БАГ?]** (не «человеческое» сообщение сервера, вроде «К сожалению продукт закончился»).
- Замечание: добавление идёт «по названию товара внутри кофейни», поэтому две кофейни с одноимёнными товарами
  различаются только городом/улицей из URL.

## 8. Корзина (`/cart`) — от пустой до отправки

Вся вкладка обёрнута в pull-to-refresh (перезагружает корзину). Пока состояние заказов не пришло — спиннер.
Над содержимым: две строки о выбранной точке — «<Город>, ул. <Улица>» (16/600) и «Открыто с HH:MM до HH:MM» (14/500).
(Если строка времени пустая — обрезка `substring(0,5)` может упасть **[не проверено]**.)

### 8.1 Состояния
| Состояние | Что видно |
|---|---|
| Ошибка загрузки корзины | «Не удалось загрузить корзину» (14/600) + кнопка «Повторить» |
| Корзина пуста | Lottie `cart.json` 300×300 и «У вас нет заказов» (20/700) — текст про «заказы», хотя это корзина |
| Корзина с позициями, заказа нет | 8.2–8.6 |
| Заказ ожидает оплаты | 8.7 (то же, но режим только-чтение + «Перейти к оплате») |
| Заказ готовится (`In Progress`) | 9.5 |

### 8.2 Карточка позиции (белая, радиус 18)
Слева: название напитка (10/600) и категория (10/500). Справа: контурная кнопка «Изменить» (22×78). Ниже — цена
позиции «N ₽» (20/700, градиент по индексу в палитре меню). Показывается **только цена позиции**; размер,
температура, добавки, вкус и количество **на карточке не отображаются**.
- **Свайп справа налево** удаляет позицию: `DELETE /api/cart/remove_from_cart/ {product_name}` (по названию, не по id
  строки; сервер удаляет первую подходящую **[БАГ?]** — при двух вариантах одного напитка можно удалить не ту),

- Явной кнопки очистки корзины нет.

### 8.3 «Изменить» (шторка `CreateOrder`, режим `update`)
Та же шторка, что в разделе 7, заполненная выбранными значениями. Отличия:
- Если у позиции `amount = N > 1`, вверху плашка «‹ Товар i из N ›»: каждая единица настраивается отдельно
  (размер/температура/добавки/вкусы). Цена наверху — сумма по всем единицам.
- Количество менять нельзя (стрелок ±, «удалить единицу» нет).
- Кнопка называется «Подтвердить»; единицы с одинаковыми настройками сгруппируются, уходит
  `PATCH /api/cart/cart/<cartId>/update/` со списком `{cart_item_id, quantity, size, temperature_type, addons, flavors}`.
- Успех: шторка закрывается, белый снэкбар «Товар обновлен!», корзина перезагружается. Ошибка: шторка закрывается,
  «Ошибка: <тело ответа сервера> cartId: <id>».
- Если корзина в этот момент не загружена — нажатие лишь запускает её перезагрузку.

### 8.4 Выбор времени готовности (`SelectTimeWidget`)
Верхняя градиентная плашка (высота 10 % экрана, пальмы по краям): «Укажите, к какому времени\nприготовить заказ».
Под ней:
- **Барабан времени** (белая карточка 170 px, два колеса «часы» и «минуты» в стиле iOS). Допустимо только окно
  **от «сейчас + 5 мин» до «сейчас + 30 мин»**: в колесе часов 1–2 значения, минуты ограничены; окно пересчитывается
  каждые 5 секунд. Изначально стоит «+5 мин».
- Синяя контурная кнопка «К этому времени» — фиксирует выбор.
- После выбора карточка заменяется на: «Приготовить заказ к:» + «HH:MM» (14/600) и кнопку «Изменить время», возвращающую
  барабан.
- Выбранное время сбрасывается при смене `cart_id` и когда корзина становится пустой (следующий заказ снова
  начинает с выбора).

### 8.5 Комментарий
Подпись «Комментарий к заказу» (12/600), поле 150 px, подсказка «Будем рады исполнить ваши пожелания 😊\nНапример:

- **Градиентная карточка «Отправить на\nподтверждение бариста »** (18/800, белый) с пальмами; внутри белая кнопка

  отменен».

## 9. Активный заказ и его диалоги

### 9.1 Модель
Клиент показывает **только последний заказ** (`orders.last`). Источник — WebSocket `/ws/orders/` (снапшот при
подключении + события), REST `GET /api/orders/orders/` — единичный аварийный снимок, если сокет не поднялся за 5 с.
События упорядочиваются по `event_seq`; более старые/дублирующие игнорируются. Сокет переподключается сам
(бэкофф 1→30 с, пинг каждые 25 с, реакция на сеть и возврат из фона); на 4001/4002 пробует обновить токен.

Статусы заказа: `New` → (бариста принял) `Waiting` → (оплата прошла) `In Progress` → (бариста завершил) `Completed`;
`Canceled` — терминальное из любого нерешённого. Оплата: `New/Pending` (ожидается) → `Paid` / `Failed`.
На сервере: бариста должен принять заказ за **90 с**, иначе автоотмена; окно оплаты **120 с** (+30 с льготы).

### 9.2 Какой диалог показывается (приоритет, `decideOrderDialog`)
1. `Canceled` и диалог не «погашен» → **«Заказ был отменен»**.
2. `Completed`, не оценён, не закрыт → **«Оценка заказа»**.
3. `In Progress` и «спасибо» не погашено → **«Спасибо за заказ!»**.
4. Бариста изменил время (`updated_time` есть) и `client_confirmed=false` → **«Изменение времени»**.
5. `New` + оплата ожидается (и заказу < 15 мин) → **«Ждем подтверждение»**.
6. Иначе — ничего.

Одновременно открыт только один диалог; новое решение ждёт закрытия текущего. Диалоги показываются поверх любого
экрана/вкладки (кроме профиля/бариста-режима) и поверх шторок.

**Механика «подтверждений» (ack):** информационные диалоги («спасибо», «отменён», «оценка») закрываются **только
после успешной записи** `POST /api/orders/orders/<id>/dialog-ack/ {"dialog":"thank_you|canceled|feedback"}`. Пока идёт
запись — кнопка в состоянии загрузки. Ошибка → красный текст «Не удалось сохранить. Попробуйте ещё раз.» и диалог
остаётся. После **двух** неудач появляется серая кнопка «Закрыть всё равно» (ack встаёт в очередь и уходит при
следующем успешном запросе). Ни один из этих диалогов нельзя закрыть тапом по фону/свайпом/системным «назад».

1. **Получение ссылки:** `POST create-invoice/ {order_id}` → `payment_url`. Спиннер по центру. Ошибка — красный

2. **Список банков:** `GET https://qr.nspk.ru/proxyapp/c2bmembers.json` (справочник НСПК). Спиннер; ошибка —
   красное «Произошла ошибка при получении доступных банков»; пусто — «На устройстве нет доступных банков».
3. **Экран выбора:** «Выберите банк для оплаты» (20/700), поисковая строка (Cupertino, фильтр по вхождению названия),
   «Оплата пройдет через приложение\nвыбранного банка» (12/600). **[БАГ?]** Под ними печатается **сырая ссылка

4. **Тап по банку:** ссылка превращается в `<schema>://<url без https://[web.]>` и открывается во внешнем приложении.

**[БАГ?]** `bloc: _sbpBLoC..add(fetch)` вызывается прямо в `build()`, поэтому перестроение шторки может заново
запрашивать счёт/банки **[не проверено на устройстве]**.

## 12. Лояльность и скидки

- Уровень: `GET /api/bonus_system/loyalty/` (загружается при старте и при каждом открытии диалога).

## 13. Push-уведомления

- Запрос разрешения — на старте (раздел 1.4).
- Токен FCM регистрируется `POST /api/users/fcm/register/ {registration_id, type_device:'ios'|'android'}` каждый
  раз, когда появляется сессия и при обновлении токена; при разлогине отвязывается `POST
  /api/users/fcm/unregister/` и удаляется.
- Канал Android `happy_island_channel` («Заказы», «Статус заказа: принят, готовится, готов, отменён», высокая важность).
- Foreground: iOS показывает системный баннер, Android — локальное уведомление того же содержимого.
  Background: обработчик только логирует.
- Тап по уведомлению просто выводит приложение на передний план; нужный диалог показывает состояние заказа.
  Deep-link'ов нет.
- Экрана «Уведомления» нет. Тексты серверных push формирует бэкенд (например, «Заказ №N готов к выдаче»).

- **Напоминание об открытии** (проверка каждые 30 с, если смена закрыта, а точка в рабочих часах): диалог без

- вкладка «Непринятые»: шторка **1. Принятие заказа** (чипы, комментарий клиента или «Клиент не оставил комментарий
  к заказу», «Ко скольки приготовить», «Осталось времени:», «Оплаченная сумма», кнопки «Редактировать» /
  «Принять заказ»; снэкбары «Заказ принят» / «Ошибка принятия заказа»);
- «Редактировать»: **1. Редактирование** — «Изменить время» (системный time-picker; «Время не может быть в

  подверждение», а при неизменённом времени ещё красная «Отменить заказ» (ошибка «Поле не может быть пустым»;
  «Заказ отменен» / «Заказ не был отменен»);

## 17. Найденные несоответствия и риски (по коду)

Отсортировано по тяжести. Ссылки — файлы репозитория приложения (`lib/src/feature/...`).

1. **[Критично, проверить на устройстве] Оплата может быть недостижима.** В рабочем дереве бэкенд гасит корзину сразу
   при создании заказа (`Island-Bali/orders/views.py`, `perform_create`, незакоммичено; раньше — только при
   завершении), а приложение показывает «Перейти к оплате» и «Ваш заказ готовится» **только для непустой корзины**
   (`cart/widget/cart_screen.dart`, `_CartViewWidget`: `basket.isEmpty → _EmptyCart` идёт раньше проверок
   `paymetRequired`/`isOrderInProgress`). После «Отправить» вкладка «Корзина» становится «У вас нет заказов», кнопка
   оплаты не рендерится. Одновременно меню в этом состоянии показывает только капибару. Нужна проверка связки
   клиент↔сервер и решение, где живёт экран активного заказа.
2. Выбор города: «Выбрать» без тапа берёт первый город, хотя радио показывает сохранённый
   (`city/widget/select_city_widget.dart:129`).
3. «Сделать предзаказ» при выбранной кофейне открывает выбор города, а при непустой корзине — только снэкбар, в меню
   не ведёт (`home/widget/home_screen.dart`, `core/util/redirect.dart`).
4. «Вернуться в меню» в «Спасибо за заказ!» не ведёт в меню (`cart/widget/order_notification_scope.dart`).
5. Профиль: телефон редактируется, но не сохраняется; после «Не сохранять» диалог сохранения возвращается при
   следующем выходе без правок (`user_profile/bloc/user_profile_actions_bloc.dart`).
6. Фамилия помечена необязательной, но без неё «Получить код» не активируется (`auth/bloc/login_bloc.dart`).
7. Франшиза: поле мессенджера запрещает цифры (`franchise/widget/apply_for_franchise_dialog.dart`).
8. СБП: на экране печатается сырой `payment_url`; запросы счёта/банков вызываются из `build()`
   (`spb/widget/sbp_bottom_sheet.dart`).
9. Сообщения об ошибках: двойной префикс «Ошибка: Ошибка при отправке заказа», технический текст `Dio` при неудачном
   добавлении в корзину (вместо «К сожалению продукт закончился»), английское «city is empty» на «Главная».
10. Клиент не отображает `availability`; не использует `BasketItem.isAvailable`; в корзине не показываются размер,
    температура, добавки и количество позиции.
11. Удаление свайпом идёт по названию товара, а не по id позиции; при нескольких вариантах одного напитка может
    удалиться не та строка. Оптимистичное удаление в `CartBloc` сравнивает `Product` со строкой и не срабатывает
    (`cart/bloc/cart/cart_bloc.dart`).
12. Количество позиции нельзя изменить в интерфейсе (только добавлением того же напитка повторно или свайп-удалением).
13. Вкладка «Меню» при ожидающей оплаты показывает только анимацию без объяснения; отдельного экрана «оплата не
    прошла» нет.
14. «Поделиться» в плеере отдаёт путь ассета; опечатка «Happpy Island Group».
15. Нет экрана «Нет связи»; при отсутствии сети часть экранов молча пустеет.
16. Транспорт: базовый URL по умолчанию — `http://` на IP, iOS разрешает произвольный HTTP — токены и данные
    заказа идут без TLS, если не передан `BASEURL` (см. также записи о секретах/авторизации в памяти проекта).
17. Строки в ARB `payTo12Minutes` называются «12 минут», а текст говорит «2 минут» — сверять с
    `PAYMENT_WINDOW_SECONDS = 120` на сервере (текст верный).
18. Неиспользуемые строки l10n: `openUntil`, `youCannotOrderLessThenOneItem`, `selectDrinkFromWeather`,
    `only15MinutesAheadAllowed` (реальное окно выбора времени 5–30 минут), карточные строки.

## 18. Рекомендуемый чек-лист сценариев (E2E)

1. Гость: главная → «Получить» → шторка входа → ввод имени/фамилии/телефона → код → возврат.
2. Гость: вкладка «Меню» → выбор города/адреса → «Заберу отсюда» → меню.
3. Гость: карточка напитка → «Добавить» → шторка входа; после входа повторить добавление.
4. Добавление: `All`/`Hot`/`Cold` напиток; размеры S/M/L; добавка с вкусом (кнопка серая без вкуса); повторное добавление
   той же комбинации (amount+1) и другой (новая строка).
5. Корзина: «Изменить» (amount>1, «Товар i из N»), свайп-удаление, выбор времени 5–30 мин, комментарий 250 знаков,
   «Отправить» без времени / со временем.
6. Заказ: ждать принятия (баристой в режиме `/staff`) → «Перейти к оплате» → банк → возврат → «Спасибо за заказ!».
   **Особо проверить пункт 17.1.**
7. Автоотмена (не принят за 90 с) → «Заказ был отменен» → «Вернуться в меню».
8. Смена времени баристой → «Изменение времени» → «Заказать»/«Отменить».
9. Завершение → «Оценка заказа» (оценить / закрыть крестиком).
10. Смена города при непустой корзине; профиль: правка имени → «назад» → «Сохранить»/«Не сохранять» → снова открыть.
11. Удаление аккаунта; выход; повторный вход.
12. Сеть: отключить на диалогах заказа (проверить «Закрыть всё равно» после двух неудач), на погоде, на СБП.

## 25. Матрица «состояние × экран» для редизайна (что обязательно нарисовать)

| Экран / оверлей | Обязательные состояния |
|---|---|
| Оболочка | город не определён / определён; гость / вошёл; вкладка активна/нет |
| Главная | гость / вошёл; погода: загрузка, успех (5 типов Lottie), ошибка; портрет / ландшафт |
| Скидка | загрузка, «прогресс», «скидка активна», ошибка (сейчас бесконечный спиннер) |
| Город / адрес | список, загрузка, нет кофеен, выбранная плитка |
| Вход | шаг 1 (пусто, частично, валидно, отправка, ошибка), шаг 2 (ввод, проверка, ошибка/тряска, таймер, доступный повтор) |
| Меню | нет кофейни, загрузка, есть данные, нет сезонного, заказ ждёт оплаты (капибара), ландшафт |
| Напитки (диалог) | загрузка, список, пусто |
| Карточка напитка | 1–3 размера, `All/Hot/Cold`, с/без добавок, добавка с вкусами (вкус не выбран / выбран), нет цены, отправка, ошибка, режим «изменить» с «Товар i из N» |
| Корзина | ошибка, пусто, с позициями (время не выбрано / выбрано, со скидкой / без), отправка, ожидает оплаты, «заказ готовится» |
| Оплата СБП | получение ссылки, список банков (поиск, пусто), ошибки, банк не установлен |
| Диалоги заказа | ожидание, смена времени, «спасибо», «отмена» (с причиной / без), оценка; у каждого — ошибка записи и «Закрыть всё равно» |
| Профиль | загрузка (пусто), ошибка, форма, «сохранить?» (ошибка), «удалить» |
| Бариста | по 4 вкладки × (пусто / список), карточки по статусам оплаты, все шторки шагов 1–3, смены |

Правило для редизайна: **то, что в разделах 5–14 перечислено как поведение, менять нельзя без согласования с
бэкендом** (статусы заказа, окна времени 5–30 мин, 90 с/120 с, ack-диалоги, формат телефона). Визуал — свободен.
